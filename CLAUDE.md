## What this is

A countdown timer: a vanilla-JavaScript PWA with no build step and no runtime dependencies.
- A 60-minute SVG clock face runs **backwards**: the hour, minute and sweep hands all turn counter-clockwise.
- A digital readout with a thin progress bar sits inside the face.
- It runs in a chrome-less Chromium app window. The owner's desktop: Kubuntu, KDE Plasma 6 on Wayland, snap Chromium. The owner's installed web apps (e.g. YouTube) are in Google Chrome; see #10.

```
countdown          bash launcher: file:// by default, --server for server.js; the timer's own Chromium profile
server.js          static file server for app/ (Node built-ins only); --exit-when-idle
app/countdown.html the page (there is NO index.html; server.js maps "/" to it)
app/app.js         all app logic (classic <script defer>; boot() at the end is the entry point)
app/styles.css     layout; container-query units; the face never below 200 px (scales down instead)
app/sw.js          service worker: network-first, cache fallback; registered only over http(s)
app/manifest.json  "id": "./" (keep it unchanged), start_url ./countdown.html, two shortcuts (5 min autostart, 25 min)
tests/             Playwright suites (optional dev tool; see tests/README.md)
```

## Hard-won facts (don't rediscover these)

- **Playwright `evaluate()` and locator reads grant user activation,** which counts as a click.
  - So sound tests record an in-page timeline and read it only afterwards (`tests/sound.js`).
  - `launcher-chime.js` only listens via `connectOverCDP`.
- **Playwright's injected keys never trigger Chromium's own shortcuts.** The lock-down's effect on the real browser was checked by hand by the owner (README).
- **Chrome's autoplay rule:**
  - The chime plays without a click only because `./countdown` starts Chromium with its **own profile** (`--user-data-dir`) plus `--autoplay-policy=no-user-gesture-required`.
  - A separate profile means a separate process, so the switch applies even when Chromium is already open.
  - Snap Chromium can't write hidden folders, so its profile lives at `~/snap/<name>/common/countdown-timer-profile`; other browsers use `~/.local/share/countdown-timer/chromium-profile`. Override with `COUNTDOWN_PROFILE`.
  - A fresh profile needs `--no-first-run`, or it stalls.
- **Closing the window stops the timer (#8):**
  - The running timer lives in `sessionStorage` and the preferences in `localStorage`; a reload keeps the timer.
  - There are no close handlers, on purpose.
- **Service workers:**
  - Never on `file://`: the browser rejects the scheme, and `app.js` doesn't try.
  - `caches` *does* exist on `file://` in Chromium, and `isSecureContext` is true there (a correction made in Exchange 83).
  - Bump `VERSION` in `sw.js` when `ASSETS` changes, or to discard old caches.
- **Heartbeat:** on localhost, each window sends `HEAD manifest.json` every 30 s. `server.js --exit-when-idle 3m` (passed by the launcher) exits after 3 min with no requests or connections.
- **Installing:**
  - The launcher's `--app=` window has no address bar or ⋮ menu, and the page blocks right-click, so the browser offers no install control there (a correction made in Exchange 107). Hence the page's own install button.
  - The install button shows only after Chromium's `beforeinstallprompt` (fired only when installable and not yet installed in that profile). Never on `file://`.
  - Measured (Playwright Chromium, Xvfb, server mode): the event fires in a normal tab *and* in a `--app=` window. A `--app=` window reports `(display-mode: standalone)`, so that media query can't be used to detect "installed".
  - A Chrome install also drops a second, identical `.desktop` file into the user's Desktop folder (the owner's is `~/desktops/default`; Exchange 111).
- **An installed app (Chromium/Chrome on Linux):**
  - It gets a 32-letter (a–p) app ID and the menu file `~/.local/share/applications/chrome-<ID>-Default.desktop`.
  - That file contains `Exec=… --app-id=<ID>` and `StartupWMClass=crx_<ID>`.
  - The manifest's shortcuts become `Desktop Action`s with `--app-launch-url-for-shortcuts-menu-item=…`.
  - This was confirmed on the owner's Google Chrome YouTube app (Exchange 100). Its `Exec=` has no `--autoplay-policy`.
